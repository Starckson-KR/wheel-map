## 2. 쓸 만한 필드와 값 분포
- crosswalks: `보도턱낮춤여부` Y 282 / N 3 (단차 cm 없음, 여부만). `점자블록유무` Y 282 / N 3(참고용, 앱 표시 범위 밖). `음향신호기설치여부` Y 66 / N 219. `보행자신호등유무` Y 282 / N 3. `횡단보도폭`·`연장`(m) 빈값 0. 이 외 차로수, 녹색·적색신호시간, 교통섬, 고원식 등. **턱낮춤 Y가 99%라 변별력이 낮음 → 실측이 필요한 이유로 쓸 수 있음.**
- toilets: `남성용-장애인용대변기수`·`남성용-장애인용소변기수`·`여성용-장애인용대변기수`와 합계(`장애인용위생시설합계`), `개방시간` 상시 184 / 정시 124, `개방시간상세`, `구분명` 개방화장실 230 / 공중화장실 78, 비상벨·기저귀교환대. 장애인용 있음 100곳. 지오코딩 사용 주소는 `geocoded`·`geocodeQuery`에 표기.
- facilities: 시설명·주소·좌표·`faclTyCd`(시설유형, 58종)·영업상태. `evalInfo`(편의시설 항목 예: "주출입구 높이차이 제거, 주출입구 접근로, 주출입구(문)")는 상세 조회된 시설만. 미조회는 `null`.
- bus-stops: `nodeid`(=id), `nodenm`, 좌표, `nodeno`, 행정동.

- 횡단보도 API 대조(저장하지 않고 비교만): API 285건 = CSV 285건, id 집합 동일(API만 0·CSV만 0), 턱낮춤·점자블록·음향신호기·폭·연장·차로수·위경도 모두 불일치 0. 필드명만 영문(`ftpthLowerYn` 등).
- **장애인편의시설 호출 한도 문제**: 상세 경로가 틀린 채로 약 70건을 호출해 낭비함(스크립트에 연속 오류 3회 중단을 추가함). 오늘 누계 81건으로 자체 상한(80) 도달 → 상세는 1건만 확보. **내일 `node scripts/prefetch.ts facilities`를 다시 실행하면 용봉동 20곳부터 상세를 이어서 받음.**
- 실패: 화장실 1곳, 편의시설 8곳은 주소 지오코딩 실패(lat/lng null).
- bus-stops 격자(위도 35.13~35.27, 경도 126.83~127.0, 간격 0.007°)는 북구 전체를 덮도록 잡은 것이며 경계 끝부분 누락 여부는 미확인. TAGO 근접 조회 517회 + 카카오 행정동 판별 1,859회.
- 지오코딩은 주소 문자열 일치 기준이라 위치가 어긋날 수 있음 → 발표 전 지도에서 표본 확인 필요.

## 4. 저상버스 필드 확인(lowfloor-check)
- TAGO 도착정보는 광주(cityCode 24)에서 정상 응답, 정류소 3곳(신안교입구 2곳·용봉2휴먼시아아파트) 모두 도착 건마다 `vehicletp` 포함.
- `vehicletp` 값: `저상버스`, `일반차량` (표본 중 저상 1~2대/정류소). 실시간 값은 저장하지 않음.
- 도착정보는 실시간 호출이 필요해 정적 사이트에서 직접 부를 수 없음(키 노출) → 앱에서는 "저상버스 노선 여부" 같은 정적 정보나 발표용 캡처로 대체 검토.

## 5. 라이선스 확인
- 횡단보도: 페이지에 이용허락범위 표기 없음 → `확인 필요`.
- 공중화장실 / 장애인편의시설: 조사 문서 기준 제한 없음(재확인은 하지 않음).
- TAGO 정류소정보: 미확인 → `확인 필요`.
- 광주버스정보: 페이지상 제한 없음(미사용).
- 개인정보: 휴대폰 번호 형태 없음 확인(원본 CSV·결과 JSON). 기관·업소 전화번호만 포함.

## 6. 다시 실행하는 방법

## 7. 광주 BIS (광주버스정보 15157923) — 활용가이드 확인 (2026-10-26)
- 가이드 원본: `data/public/raw/OPENAPI활용가이드_광주버스 v1.0.docx`. 기준 URL `http://apis.data.go.kr/6290000/gj_bis/`, REST(GET), `serviceKey` + `resultType=json`(기본 xml). 응답은 JSON에서 `RESPONSE` 아래에 들어옴(가이드 예시와 약간 다름).
- 동작 확인(승인됨): `stationInfo`, `arriveInfo`, `lineInfo` 호출 성공(`SUCCESS`). `lineStationInfo`·`busLocationInfo`는 호출하지 않음.

| 기능 | 요청 | 주요 응답 필드 |
|---|---|---|
| `stationInfo` 정류소 목록 | 변수 없음(1회 호출로 광주 전체 4,746개) | `BUSSTOP_ID`, `BUSSTOP_NAME`, `LATITUDE`, `LONGITUDE`, `ARS_ID`, `NEXT_BUSSTOP`(방향), `NAME_E` |
| `arriveInfo` 도착정보 | `BUSSTOP_ID` | `LINE_ID`, `LINE_NAME`, `REMAIN_MIN`, `REMAIN_STOP`, `LINE_KIND`, **`LOW_BUS`** |
| `busLocationInfo` 버스위치 | `LINE_ID` | `BUS_ID`, `CARNO`, **`LOW_BUS`**(저상버스구분), `CARDY`(차량유형), `CURR_STOP_ID`, `SEQ` |
| `lineInfo` 노선 목록 | 없음 | `LINE_ID`, `LINE_NAME`, 기점·종점, 운행시간·배차간격, `LINE_KIND` |
| `lineStationInfo` 노선-정류소 | `LINE_ID` | 노선별 정류소 순서 |

- **저상 여부 필드 있음**: `arriveInfo`·`busLocationInfo`의 `LOW_BUS`(실제 응답에서 `"1"`=저상, `"0"`=일반 확인; 가이드에 값 설명은 없어 이 해석은 응답 관찰 기준). 도착정보는 TAGO의 `vehicletp`와 같은 용도.
- 정류소 목록에는 **행정구역 필드가 없음**(좌표만). 북구 판별은 카카오 행정동 기준. 가이드 표의 위도/경도 설명은 서로 바뀌어 있으나 응답 값은 정상(스크립트가 값 범위로 보정).
- 정류소 대조(북구, 좌표 40m 이내를 같은 정류소로 봄): BIS 669개 / TAGO 격자 수집 776개. BIS에만 있는 정류소 20개(석곡동 등), TAGO에만 있는 정류소 21개. **BIS가 더 완전하지 않음** — TAGO가 양방향·타 사업자(예: 나주교통) 정류소를 더 포함하고, 양쪽 모두 누락이 조금씩 있음. 용봉동은 BIS 48 / TAGO 55.
- 결과 파일: `data/public/bus-stops.bis.json`(`bus-stops.json`은 덮어쓰지 않음). 원천 선택은 파일 선택으로 대체: 실행 `node scripts/prefetch.ts bus-stops-bis`. BIS id와 TAGO nodeid는 서로 다름(도착정보 호출 시 각 API의 id를 써야 함).
- 호출 수: BIS 정류소 목록 재실행으로 약 5회 + 확인 2회. 카카오 행정동은 TAGO 후보와 40m 이내면 재사용하고 나머지만 호출(상한 1,500/회 × 3회 실행).
