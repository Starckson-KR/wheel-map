# 토스 디자인 언어 조사 요약과 적용 기록

작성일 2026-10-26. 북구동행지도 UI 개편(토스 맛)의 근거 문서다. 확인한 것과 확인하지 못한 것을 나눠 적는다.
토스 앱 코드·이미지·로고·글꼴 파일은 쓰지 않았고, 공개된 가이드의 **원칙만** 적용했다.

## 1. 공식 가이드에서 확인한 것 (앱인토스 미니앱 UI/UX 가이드)

출처: https://developers-apps-in-toss.toss.im/design/consumer-ux-guide.md (원문 요약본을 읽었고, 전체 원문은 출처에서 확인해야 한다)

| 영역 | 확인한 내용 | 이 프로젝트의 적용 |
|---|---|---|
| UX 라이팅 | 모든 문구는 **해요체**. 능동형·긍정형을 먼저 쓴다. 과한 경어(`~시겠어요?`, `께`)와 명사+명사 한자어를 피한다. `되어요`는 `돼요`로 통일한다 | 화면 문구 전체를 해요체로 바꿨다. `~합니다`·`~하십시오`를 없앴다 |
| 다이얼로그 버튼 | 왼쪽 버튼은 **닫기**로 통일하고 `취소`는 쓰지 않는다 | 모든 닫기 버튼을 `닫기`로 통일(지도에서 위치 고르는 중 안내의 `취소`도 `닫기`) |
| 예외 | 수동형·부정형은 서비스 종료·정책상 제한·민감한 상황에서만 이유와 함께 쓴다 | 접수·법령 안내는 사실을 그대로 두고 어미만 바꿨다 |
| 다크패턴 방지 | 진입 즉시 바텀시트, 뒤로 가기 시 바텀시트, 거절 선택지 없음, CTA 예측 불가 등은 출시 불가 | 첫 화면에 팝업·광고성 시트를 띄우지 않는다. 시트는 사용자가 눌러야 열린다. 버튼 이름은 결과를 그대로 말한다(`문제 제보하기`, `등록하기`) |
| 그래픽 | 한 화면에 핵심 그래픽 하나, 장식 효과(파티클·과한 그라데이션) 금지, 오류가 아닌데 느낌표 금지, 기다릴 필요 없으면 로딩 애니메이션 금지 | 장식 그래픽 없이 글자·여백·색 면으로 구성. 로딩은 문장으로만 알린다 |
| 해상도·안전 영역 | 기준 해상도 하나를 정하고 스케일링. 세로형 약 360×640~420×740. 노치는 Safe Area로 처리 | 375×812 기준으로 설계, `viewport-fit=cover`와 `env(safe-area-inset-*)` 사용 |
| 탭바 | 필수가 아님. 쓰면 2~5개, 토스 하단 탭과 겹치지 않게 | 하단 탭바를 두지 않았다(지도 홈 + 시트 구조) |
| 브랜드 | 브랜드 이름은 한글, 색은 six-digit 헥스(예 `#3182F6`) | 이름 `북구동행지도`. 기준 파랑 `#3182f6` 계열 사용 |

## 2. 공개 자료에서 확인한 것 (출처 표시, 공식 명세 아님)

- **TDS 핵심 컴포넌트 11종**: Badge, Border, BottomCTA, Button, Asset, ListRow, ListHeader, Navigation, Paragraph, Tab, Top. 이 페이지에는 높이·모서리·색 수치가 없다. 출처: https://developers-apps-in-toss.toss.im/design/components
- **TDS 사용 조건**: TDS와 관련 자료의 지식재산권은 토스에 있고, 파트너사는 앱인토스 서비스를 쓰는 범위에서만 쓸 수 있다. 위반하면 서비스가 중단될 수 있다. 같은 출처. → 이 프로젝트는 TDS 코드를 가져오지 않고 직접 만든 CSS로 비슷한 **원칙**만 따랐다. 앱인토스 출시 단계에서는 공식 TDS(`tossmini-docs.toss.im/tds-mobile`) 컴포넌트로 교체하는 방안을 따로 검토한다.
- **UX 라이팅 원칙**: 제품 글쓰기 원칙으로 보이스톤을 통일, 의미에 기여하지 않는 단어를 빼는 "잡초 뽑기", 사용자 효용 우선(과장·자극 문구 지양). TDS 컴포넌트 규칙의 예로 바텀시트 제목은 한 줄, 단일 액션 버튼은 `~하기`, 취소 버튼 대신 `닫기`·`다음에`가 소개돼 있다. 출처: https://toss.im/tossfeed/article/uxwriter-interview
- **단순함 원칙**: 불필요한 단계 제거, 화면마다 할 일 하나, 오류는 필요할 때만 안내, 입력 최소화, 첫 화면 최소화. 출처: https://toss.im/tossfeed/article/importance-simplicity
- **"한 화면 한 가지 행동"**: 공식 자료에서 이 문구 자체는 확인하지 못했다(제3자 정리에만 나온다). 위 단순함 원칙의 해석으로만 쓴다.

## 3. 제3자 정리에서 가져온 수치 (공식 값 아님, '추정')

출처: 오빠두 디자인 시스템 갤러리 https://www.oppadu.com/tools/design-systems-site/brand/toss.html (공식 문서가 아니라고 명시돼 있음)

- 파랑 계열 500 `#0064FF`, 회색 `#F2F4F6`(100) · `#E5E8EB`(200) · `#4E5968`(800) · `#191F28`(900). 한글은 Pretendard.
- 버튼 모서리 12px, 카드 14px, 시트 큰 모서리 20px대, 4px 간격 단위, 컨테이너 좌우 20px, 본문 15~17px.
- **공식 가이드의 예시 색은 `#3182F6`** 이라서 이 프로젝트는 그 값을 기준으로 삼았다. 흰 글자와의 대비가 3.71이라, 채움 버튼은 `#2272eb`(4.49)를 쓴다.
- 위 수치는 확인되지 않았으므로 **추정**으로 보고, 최종 값은 이 프로젝트의 `src/styles/tokens.css`에서 정한다.

## 4. 글꼴과 라이선스

- **Pretendard**: SIL Open Font License 1.1. 상업적 이용·재배포 가능, 글꼴 단독 판매와 라이선스 변경만 금지. 출처: https://github.com/orioncactus/pretendard (산돌구름 안내 https://www.sandollcloud.com/free-font/16951/Pretendard 도 같은 내용). `index.html`에서 jsDelivr CDN(`pretendardvariable-dynamic-subset`)으로 불러오고, 실패하면 시스템 글꼴로 돌아간다. 파일은 저장소에 넣지 않았다.
- **Toss Face·Toss Product Sans**: 이번 조사에서 라이선스·배포 채널을 확인하지 못했다. 쓰지 않았다.
- 토스 로고·상표·아이콘·3D 이미지: 쓰지 않았다. 아이콘은 직접 만든 SVG(검색, 닫기, 뒤로, 내 위치, 체크, 화살표)와 기존 이모지다.

## 5. 이 프로젝트의 디자인 규칙 (tokens.css가 기준)

| 항목 | 값 |
|---|---|
| 파랑 | 500 `#3182f6`(강조·진행 바·선택 테두리), 600 `#2272eb`(채움 버튼), 700 `#1b64da`(글자 링크), 50 `#e8f3ff`(연한 면) |
| 회색 | 900 `#191f28`(강한 글자), 800 `#333d4b`, 600 `#6b7684`(보조 글자, 흰 바탕 대비 4.6), 100 `#f2f4f6`(면), 200 `#e5e8eb`(선) |
| ○△X | ○ `#0f7f55`(흰 글자 5.0), △ `#f2a900`(어두운 글자 `#3d2400`), X `#d0342c`(흰 글자 5.0), 평가 없음 `#6b7684`. 모두 글자(○△X)를 함께 쓴다. 옛 색(`#2e7d32` `#a85a00` `#c62828`)에서 채도·명도를 맞췄고 의미는 같다 |
| 글자 | 제목 24/800, 머리글 20/800, 부제 17, 본문 16, 작은 글 14, 보조 13. 자간 -0.01em 안팎 |
| 간격 | 4px 단위, 화면 좌우 20px(`--gutter`) |
| 모서리 | 8 · 12(버튼·입력) · 16(카드) · 24(시트) · 999(칩) |
| 터치 | 버튼·입력 최소 44px(`--touch`), 시트 손잡이 28px, 지도 핀은 보이지 않는 터치 영역을 8px 넓혔다 |
| 움직임 | 누르면 `scale(.97)` 120ms, 시트 280ms `cubic-bezier(.32,.72,0,1)`, 나타날 때는 ease-out만 쓴다. `transform`·`opacity`만 움직인다. `prefers-reduced-motion`이면 움직임을 끈다 |
| 다크 모드 | 토큰만 준비(`:root[data-theme='dark']`). 자동으로 켜지지 않는다 |

## 6. 화면 구성 (발표 슬라이드 5단계 대응)

슬라이드: 위치 표시 → 문제 분류 → 현장정보 기록 → 경로 추천 → 개선 상태 관리.

| 슬라이드 | 화면 |
|---|---|
| 01 위치 표시 | 지도 홈. 위쪽 카드(앱 이름·레이어·시연 도구·검색), 아래 시트(지금 보이는 곳의 장애요소 개수와 목록, 내 위치 버튼) |
| 02 문제 분류 | 제보 1단계 `어떤 문제를 만났나요?` 유형 카드(아이콘·설명·고정형/일시형) |
| 03 현장정보 기록 | 제보 2단계 위치, 3단계 사진·설명·직접 잰 값, 4단계 확인 |
| 04 경로 추천 | 길찾기 결과: 판정 카드, 경로 비교 카드(가장 짧은 길/돌아가는 길), 버스 타기 불편 정류장, 도착지 출입 불편 |
| 05 개선 상태 관리 | 제보 현황(전체·진행 중·완료), 상태 배지, 처리 기록 타임라인, 행정 화면 |

시연 장치(시연 사용자·접수 방식·시간 앞당기기·시연 데이터)는 위쪽 카드의 `시연 도구` 버튼 하나로 모았다. 모의 접수 모드에서는 `시연용 모의 연동 · 실제 접수는 되지 않아요` 표시가 어느 화면에서나 계속 보인다.

## 7. 다음 단계 제안 (앱인토스 출시 대비)

- 공식 TDS 컴포넌트(ListRow, BottomCTA, Tab 등)로 교체할지 검토. 사용 조건이 앱인토스 서비스 안으로 제한되므로 출시 시점에 맞춘다.
- Pretendard를 CDN이 아니라 번들에 포함할지 결정(오프라인·심사 환경 고려).
- 내비게이션 바 규격(게임/비게임 가이드)은 원문 링크가 없어 확인하지 못했다. 출시 준비 때 콘솔 가이드에서 확인한다.
