## 1. 한 줄 요약
- 모두의 AI실험실은 **「AI 모델 API를 직접 주는 곳」이 아니라** ① 노코드 앱 만들기 도구(바이브코딩, 1인 4만 포인트), ② 무료 클라우드(CPU)·개발지원도구, ③ 연계 서비스 **디지털융합플랫폼(portal.koreaconnect.kr)의 공공 데이터·API 30만여 건**을 묶어 둔 곳이다. 우리 앱에 바로 붙일 AI 모델 엔드포인트는 확인되지 않았고(FAQ: 외부 모델 API 키 지원 안 함), 쓸 만한 것은 **지도·교통·접근성 데이터/API**와 **무료 클라우드·n8n·RAGFlow 같은 도구**다.
- 모든 자원은 **2026-12-31 사업 종료 시 일괄 회수**된다. 발표가 12월이면 시기는 맞지만 장기 운영 기반으로는 못 쓴다.

## 3. 추천 순서 (최대 3개)
1. **지도·접근성 데이터 후보 확인 후 미리 받아 JSON 저장**(휠체어·저상버스·접근성 검색 결과 중 광주 북구에 해당하는 자원) - 키가 브라우저에 안 나가고 발표 화면에 「공공데이터 연계」를 바로 보일 수 있다.
2. **대중교통 길찾기(ODsay) API를 Worker 경유로 연동 검토** - 길찾기가 이 앱의 핵심 기능이라 효과가 크다(단, 이미 쓰는 경로 엔진과 중복·광주 지원 여부는 확인 필요).
3. **n8n(개발지원도구)로 공공데이터 정기 수집 시험** - 발표 뒤 갱신 자동화에 도움이 되나, 12/31 회수 때문에 발표용 보조 이상은 어렵다.

## 4. 못 쓰는 것과 이유
- **AI 모델 API(LLM·이미지·음성)**: 공개된 모델 목록·엔드포인트·OpenAI 호환 안내가 없고, FAQ가 외부 모델(Claude·Gemini·GPT) API 키와 GPU를 개별 신청으로 지원하지 않는다고 밝힘. 현재 Cloudflare Workers AI(qwen3)가 이미 있으므로 대체할 이유도 약함.
- **바이브코딩 결과물을 본체로 배포**: 내부 데이터 반출 기능 없음, 30분 무조작 시 링크 종료, 12/31 종료.
- **GPU·파인튜닝·노트북·샌드박스**: 메뉴 없음(GPU는 선정된 팀 프로젝트에만, 경진대회 선정 12팀 등 별도).
- **유료·상업 운영**: 약관 13조가 승인 없는 유료 운영·재판매 금지. 앱인토스 출시 같은 상업 전개에는 사전 승인 필요(발표용 무료 시연은 문제 소지 낮으나 확인 필요).
- **경진대회·AI 라우터 직접 호출**: 접수 마감(8/18~9/6), 라우터는 내부 기능이고 외부 노출 정보 없음.

## 5. 확인 못 한 것
- 로그인 후 전부: My Studio, 바이브코딩 내부(모델 선택·포인트 화면), 클라우드 신청서, API/데이터 신청, 문의, 포럼.
- 제공 모델 이름·크기·한국어 지원(사이트 화면에는 목록 없음. 기사 기준 EXAONE 4.5, GPT-5.6 Terra, Gemma 4가 출범식 시연에 언급됐다는 보도만 있음).
- 호출 한도(분·일·월), 언어별 샘플 코드, OpenAI 호환 여부, 데이터셋별 용량·형식·광주 지역 포함 여부.
- 우리 웹앱이 이 플랫폼 밖에서 API를 호출하는 것이 약관상 허용되는지(FAQ는 디지털융합플랫폼 외부 연계는 직접 구현이라고만 안내). 상업 이용 일반 허용 여부.
- 사용자의 신청 여부·키 발급 여부(이 조사에선 「확인 못 함」).
- 사이트 본문 화면 URL은 모두 https://aitestbed.kr/ 하위(`/faq`, `/guide`, `/tb-intro`, `/notices`, `/privacy` 등)이며 약관 시행일은 2026-08-03.

## 6. 키 관리 원칙
키(디지털융합플랫폼 `api_user_key_id` 등)는 `.env`와 Cloudflare Worker secret에만 두고 브라우저 코드에는 넣지 않는다. 공공 데이터는 가능한 한 미리 받아 JSON으로 저장한다.

### 7-2 ODsay 사실 확인과 우리 코드에서 바꿀 곳

**확인한 것**(출처: 포털 상세 https://portal.koreaconnect.kr/market/mk/getMkApiDetail?clsBun=0&pageNo=1&drsTcd=02&drsno=41980be6a20e4d6296fa68ceb06c4d51 , ODsay 공식 https://lab.odsay.com/guide/releaseReference , https://lab.odsay.com/guide/guide)
- 제공: (주)아로정보기술, 교통물류, 등록 2026-04-15, 수정 2026-04-22, REST. 라이선스 「출처표시」(구체 문구는 상세에 없음).
- **포털 호출 형식**: `GET https://api.koreaconnect.kr/01/1/2604071749001710344ODS/LOGIS/v1/api/searchPubTransPathT`, 헤더 `api_user_key_id`(발급받은 키 아이디) 하나. ODsay 원본 주소는 `https://api.odsay.com/v1/api/searchPubTransPathT`(파라미터 `apiKey`). **우리는 포털 키를 쓰므로 koreaconnect 주소·헤더를 쓴다.**
- 요청 파라미터: `SX,SY`(출발 경도,위도), `EX,EY`(도착), `OPT`(0 추천, 1 타입별), `SearchType`(0 도시 내만), `SearchPathType`(0 전체·1 지하철·2 버스), `output`(json 기본·xml), `lang`(0 국문 기본).
- 응답: `result.path[]` → `pathType`(1 지하철, 2 버스, 3 버스+지하철), `info`(totalTime[분], payment, totalWalk, busTransitCount, mapObj …), `subPath[]` → `trafficType`(1 지하철, 2 버스, 3 도보), `distance`, `sectionTime`[분], `lane[]`(버스는 `busNo`, `type`(노선 종류 코드), `busID`), `startName/endName`, `startX/Y`, `endX/Y`, `startLocalStationID`, `startArsID`, `passStopList.stations[]`(`stationName`, `x`, `y`, `isNonStop`).
- **구간 선(좌표)**: 길찾기 응답에는 선이 없고 `info.mapObj`를 `loadLane`(`https://api.odsay.com/v1/api/loadLane?mapObject=…`)에 넣어 `result.lane[].section[].graphPos[]`(x,y)를 받는다. 포털에서는 「버스/지하철 노선 그래픽 데이터 검색」이 별도 자원이다(상세는 안 열어 봄). 대안: `passStopList` 정류장 좌표를 이어 선으로 쓰기.
- 오류코드: -8 입력값 오류, -9 필수값 누락, 3·4·5 출발/도착 정류장 없음, 6 서비스 지역 아님, -98 출발·도착 700m 이내, -99 결과 없음.
- 같은 아로정보기술 자원이 포털에 23건: 길찾기·시간표(3), 정류장·POI(5), 지하철역(3), 버스노선(3), 시외·고속·열차·항공(8), 도시코드 조회(1). 우리에게 쓸모 있는 후보는 「버스정류장 세부 정보」「버스노선 상세정보」(상세 미확인).
- **광주 지원**: ODsay 공식 문서에 「전국」이라는 소개와 광주 도시코드 5000(지하철 노선도)·광주 BIS 제공자 코드 8·광주1호선(51)이 나오고 포털 상세에도 광주1호선 코드가 있다. 그러나 **길찾기가 광주 시내버스를 지원한다는 명시 문구는 못 찾았다**(지원범위 페이지는 목록이 열리지 않음). → 키를 받은 뒤 용봉동→전대치과병원 같은 쌍으로 시험 호출 1번이 필요하다.
- **한도·요금**: 공식 가이드에 「애플리케이션별 일 제한 호출수」가 있다는 말만 있고 숫자는 없다. 계정당 앱 3개, 키 1개당 URI·IP 5개까지, 기본 통계 12시간 전까지는 무료·그 이상은 유료. **포털 상세에는 한도·무료 여부 표기 없음 → 확인 필요.** (개인 블로그에 「일 1,000건 6개월 무료」라는 오래된 글이 있으나 비공식이라 근거로 쓰지 않음.)
- **저상버스 정보**: 응답 명세에서 저상(lowBus) 필드를 **확인하지 못했다**(`lane.type`은 노선 종류 코드이고 값 의미표는 못 봄). 저상 여부는 지금처럼 광주 BIS `LOW_BUS`를 유지하는 것이 안전하다.
- 키 노출: 공식 가이드가 키를 외부에 노출하지 말라고 하고 일부 API는 CORS 때문에 서버 호출만 가능하다고 한다 → 중계 필요.

### 8-2 추천 순위 (발표 효과 · 붙이기 쉬움 순)
1. **신호잔여시간 API** — 실시간 숫자가 화면에 움직이는 시연 효과가 가장 크다. 단 광주 교차로 포함 여부는 신청 전에 문의처로 확인해야 한다(안 되면 순위 하락).
2. **북구 파일 묶음(그늘막·옐로카펫·침수피해·대기질 신호등)** — 모두 CSV·제한없음·북구 전용·위치 있음이라 미리 JSON으로 저장해 레이어로 붙이기 가장 쉽고, 날씨·계절 기능과 이어진다. 그늘막은 「횡단보도 인근」이라 길찾기와도 맞는다.
3. **광주 C-ITS 소통 통계·교통 흐름 API** — 광주 자료이고 제한없음이라 길찾기 시연에 「지금 도로 상태」를 얹을 수 있다. 응답은 표준노드링크ID 기준이라 우리 보행망과 짝지으려면 별도 작업이 필요하다(확인 필요).
4. **한국조폐공사 지역사랑상품권 판매정책·운영정보** — 혜택알림 화면에 실제 할인율·월 한도를 넣을 수 있다. 광주 북구 지역코드로 거르는 방식이고 광주 데이터 존재 여부는 호출해 봐야 안다.
5. **한국관광공사 무장애 여행 정보(+사회보장정보원 장애인편의시설)** — 휠체어 접근 정보를 공식 출처로 보강한다. 이미 있는 편의시설 1,697곳과 겹치는 부분이 있어 보강·대조용이다.

### 8-4 MCP 53건 중 쓸 것
- 앱 런타임에는 쓸 것 없음(7절과 같음). 개발 중 조사 도구로만: 「디지털융합플랫폼 오픈API 목록 조회」(포털 자원을 코드에서 찾을 때), 건강보험심사평가원 약국정보, 식약처 e약은요, 소방청 전국 구급·119 현황(통계 근거). 「현재 날씨 API」「3시간 간격 예보 5일」「현재 대기오염 API」는 OpenWeather 해외 서비스라 국내 날씨는 날씨 담당 조사와 중복이다.
- 목록 전체: 포털 마켓 MCP 탭(53건).

### 8-5 확인 필요
- 신호잔여시간: 광주 지자체 포함 여부, 호출 한도, 라이선스 표기, 사용 승인 방식.

- 무장애 여행 정보에 광주 북구 자료가 있는지, 앱 편의시설과 중복 정도.

- 명세 기준 주소 `https://apis.data.go.kr/B551982/rti` 뒤에 기능 경로가 붙는다. 공개 화면에는 경로가 없어 `crsrd_map_info`(교차로 맵 정보)와 `tl_drct_info`(신호잔여시간)로 호출해 보니 둘 다 응답했다(경로 이름은 추측해 맞춘 것이라 제공기관 문서와 대조는 못 함).
- 교차로 맵 응답 필드: `stdgCd`, `lclgvNm`, `crsrdId`, `crsrdNm`(예: 이촌역앞), `mapCtptIntLat`, `mapCtptIntLot`, `laneWdth`, `lmtSpd`, `regDt`, `totDt`. 요청: `pageNo`, `numOfRows`(1000까지 됨), `type=JSON`, `stdgCd`.
- 신호잔여시간 응답은 울산에서만 확인: 방향 접두(`nt` 북·`et` 동·`st` 남·`wt` 서·`ne`·`se`·`sw`·`nw`) + 종류 접두(`Bs` 버스·`Bc` 자전거·`Lt` 좌회전·`Pd` 보행·`St` 직진·`Ut` 유턴) + `sg` + `RmndCs`(잔여시간) 또는 `SttsNm`(신호 상태명)으로 필드가 만들어진다(예: `ntStsgRmndCs`="3000", `etLtsgSttsNm`="stop-And-Remain"). 보행(`Pd`)이 따로 있으나 울산 샘플은 보행 칸이 비어 있었다. 잔여시간 단위(0.1초로 보임)는 **확인 필요**.
- 서울 신호잔여시간은 교차로 맵엔 있어도 호출 시점에 NODATA였다(상시 제공이 아닐 수 있음, 확인 필요).
- 결론: 광주 용봉동 교차로가 없어 길찾기 「보행 신호 N초 남음」은 광주에서 불가. 제공기관 문의처(02-2031-9337)에 광주 확대 계획을 물어볼 수는 있다. 발표에서는 「다른 도시엔 있는데 광주는 아직 없다」는 정책 제안 근거로만 쓸 수 있다.

### 10-3 광주 C-ITS (15098622)
요청 주소 `https://apis.data.go.kr/6290000/gjcitsdata/` + 기능 이름. 응답은 `resultCode`(0이 정상), `resultMsg`, `data` 배열.

| 기능 | 호출 이름(확인됨) | 파라미터 | 필드 | 확인 결과 |
|---|---|---|---|---|
| 소통 통계 | `getTrafficStatistic` | `offerDate`(YYYYMMDDHH) | `prcnDtm`, `linkId`, `speed`, `travelTime`, `grade` | 오늘 00시 자료까지 옴(예: linkId 1750000100, speed 58.3, grade "없음"), 20시는 비어 있어 약 1~2시간 늦다. 과거(2025-11-19 12시)는 빈 응답이라 보관 기간 짧음 |
| 스쿨존 | `getSchoolZone` | `offerDate`(YYYYMMDD, 2021-12-31로 호출) | `zoneId`, `name`, `address`, `offset`(폴리곤 좌표열), `longitude`, `latitude`, `modifyDate` | 418곳 전부 광주, **북구 117곳**, 용봉동 기준 1.5km 안 25곳(민족사관유치원 0.3km, 용주초 0.9km 등). 변경일은 2021-12-31~2022-02-23이라 최신 아님 |
| 주정차 단속구간 | `getParkingZone` | 없음 | `zoneId`, `name`, `offset`, `longitude`, `latitude` | 258곳, 1.5km 안 21곳(전대입구사거리 0.5km, 북구청 0.5km, 용봉동행정복지센터 0.6km) |
| 교차로 교통 흐름(LOS) | 이름 못 찾음 | `offerDate`(월), `tasType` | `nodeId`, `nodeName`, `delay`, `levelOfService` | **확인 필요**(이름 12개 추측 모두 서비스 없음 오류) |
| 통합주차 | 이름 못 찾음 | 없음 | `id`, `name`, `address`, `totalAbleCnt`, `ableCnt`, `modifyDate` | **확인 필요**(위와 같음) |

- 소통 통계는 `linkId`(표준노드링크) 기준이라 우리 보행망에 붙이려면 링크 좌표표가 별도로 필요하다(이번에 못 찾음, 확인 필요). 소통 등급 `grade`는 자정에 「없음」이어서 등급 값 종류도 확인 필요.
- 보행 약자용으로 쓸 만한 것은 **스쿨존·주정차 단속구간**이다. 둘 다 거의 변하지 않는 자료라 실시간 호출보다 사전 수집이 맞다.
- 호출 한도 표기는 포털에 있음(10,000/일). 시험 호출은 이 API에 약 20번 썼다(기능 이름 찾느라).

### 10-4 지역사랑상품권 (15125217, 15108296)
- 판매정책 기능 두 개: `/paper`(지류, 페이징 `pageNo`·`numOfRows`)와 `/cardMobile`(카드·모바일, `page`·`perPage`). 필터는 `cond[usage_rgn_cd::EQ]`, `cond[crtr_ymd::EQ]`. **필터 값은 인코딩하지 않은 그대로(대괄호) 붙여야 먹는다**(인코딩하면 필터가 무시되어 전체 93,270건이 나옴).
- 응답 필드(확인): `crtr_ymd`(기준일), `dscnt_rt`(할인율), `mm_prchs_lmt_amt`(월 구매한도), `pvsn_inst_cd`, `usage_rgn_cd`. 예: `20261101`, 할인율 12, 한도 300000, 지역 44790. 기준일 20261101 스냅샷은 88개 지역(코드 앞 두 자리 11·12·31·41·43·44·47·48·51·52)이고 광주(29)·전남(46)은 없다. 지류 쪽도 북구 29170은 0건.
- 따라서 `docs/상품권_가맹점_혜택_조사.md`가 말한 부끄머니 15%·광주상생카드는 이 API로 **확인도 갱신도 못 한다**(겹치는 정보 없음, 더 최신도 아님). 앱의 북구 정보는 계속 북구 공지 기준이어야 한다.
- 운영정보(`/operationsV2`, 필터 `cond[usage_rgn_cd::EQ]`·`cond[crtr_ym::GTE]`)는 광주광역시 전체 코드 29000만 나오고(예: 2026-01 `card_pblcn_qty`=48947, 휴대 가입 0, 지류 판매 0) 북구·동구·광산 코드는 0건. 혜택 정보가 아니라 발행 통계라 앱 화면에는 쓸모가 낮다.

### 10-5 앱에서 쓸 곳 제안과 순서
1. **스쿨존·주정차 단속구간 레이어(추천 1순위)**: 화면 「동행지도」에 「어린이보호구역」 칩과 「주정차 단속」 칩. 문구 예 「이 길은 어린이보호구역이에요(속도 제한)」. 방식: 사전 수집(스크립트로 JSON 저장, 용봉동 반경만 남김), Worker·키 노출 없음, 폴리곤은 `offset` 좌표열. 스쿨존은 2022년 자료라 화면에 「자료 기준 2022년」을 표시하지 않으면 최신처럼 보일 수 있다(문구는 최소화 원칙에 따라 정보 버튼 안에).
2. **소통 통계는 시연 장식 수준**: 링크 좌표표가 없으면 지도에 못 올린다. 좌표표를 찾기 전에는 보류.
3. 신호등·상품권은 **쓰지 않는다**(광주 자료 없음). 발표 때 「실시간 보행신호는 서울·제주·울산에만 있고 광주는 없다」를 정책 제안 근거로 한 줄 쓸 수 있다.
4. 후속 확인: C-ITS 교통 흐름·통합주차 기능 이름(제공기관 문서 또는 신청 화면의 서비스 목록), 소통 링크 좌표표.
