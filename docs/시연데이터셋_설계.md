# 대규모 시연 데이터셋 설계

> 작성 2026-11-11(예약 작업 `wheelmap-demo-dataset`). 사용자와 11/11 새벽 합의한 설계를 현재 코드 구조에 맞춰 정리했다. 구현 중 달라진 점은 이 문서 맨 아래 "구현 메모"에 덧붙인다.
> 모든 데이터는 **가상**이다. 데이터(`demo: true`, 닉네임, 메모 "(시연)")와 화면(띠·핀 상세) 양쪽에 표기한다.

## 1. 현재 구조(확인함)
- 제보 저장: `lib/reportStore.ts`의 zustand, localStorage `wheelmap.reports`(Report[] JSON). 사진은 IndexedDB. `resetAll`이 전부 비운다.
- 시연 사용자: `DEMO_USERS` 5명 고정(시민 A·B·C, 검증자, 공무원). `userName(id)`이 이름을 찾는다. 선택값은 `wheelmap.demoUser`.
- 기존 시연 데이터: `lib/demoData.ts` `buildDemoReports(seeds, now, newId)` 10건(팀 조사 지점 id로 만든 `seedId` 건). `fillDemo`는 `demo` 건이 하나라도 있으면 다시 안 만든다.
- 점수·랭킹: `rewards.ts`(computeRewards), `ranking.ts`(주·월), 개선 현황 `progress.ts`, 보고서 `reportStats.ts`, 재발 `recurrence.ts`. 모두 reports(+history·verification·action)에서 계산한다.
- 위치 후보 자료: `data/public/crosswalks.json`, `bus-stops*.json`, `facilities.json`, `toilets.json`(`lib/publicLayers.ts`가 앱에서 읽음).
- 시연 도구: `components/DemoTools.tsx`. 모의 연동 띠 `MockStrip`(같은 파일)이 지도 위 띠 자리.

## 2. 규모와 분리
| 항목 | 값 |
|---|---|
| 활성 사용자 | 약 300명 (id `crowd-001`~, 닉네임은 가상) |
| 가상 지점 | 약 150~180개, 용봉동 안. 위치 후보(횡단보도·정류장·편의시설)가 모자라면 개수를 줄이고 이유를 보고 |
| 제보 | 약 600~750건 (한 지점에 여러 건 가능 = 재발·중복·재확인) |
| 사진 | 없음 |

- 기존 "시연 데이터 채우기"(10건)는 그대로 둔다. 새 버튼 **"대규모 시연 데이터 채우기"**를 추가한다.
- 대규모 건은 `demo: true` + 별도 표지 `demoSet: 'large'`(Report에 선택 필드 추가)로 구분한다. 이미 대규모 건이 있으면 다시 만들지 않는다. 기존 10건이 있어도 함께 채울 수 있다(10건은 건드리지 않음).
- 기본 지도·팀 조사 34곳·실제 집계(시드)는 건드리지 않는다. 초기화(`resetAll`) 때 같이 비워진다. 사용자 명부도 함께 비운다.

## 3. 생성 규칙 (시드 고정)
- 시드 고정 난수(예: mulberry32, 시드 상수). 같은 `now`면 같은 결과.
- 날짜는 "채우는 시점 `now` 기준 며칠 전". 90일 안에 고르게(최근에 조금 더 몰림), 주간·월간 랭킹과 분기 보고서가 언제 열어도 차게 한다. 이번 주(월~일)에도 최소 8~12명이 점수를 얻도록 최근 7일에 일정 비율을 둔다.
- **장애요소 유형 비율(안)**: 파손 노면 22%, 계단·턱 20%, 좁은 보도 15%, 경사 12%, 불법 주정차 12%, 쓰레기 8%, 신호기(횡단보도) 6%, 기타 유형 5%. 유형 이름은 기존 `reportTypes.ts` 것만 쓴다.
- **판정 ○△X**: ○ 15%, △ 45%, X 40% 근처(조치 완료 후 재확인 통과 건은 ○).
- **위치 성격(locationKind)**: 후보 종류에 맞춰 기존 값 사용(버스정류장·횡단보도·신호·구·시 도로의 보도·대학 캠퍼스 내부 등). 소관 기관 후보가 없는 조합(예: 쓰레기+버스정류장)은 만들지 않는다.
- **사용자 활동 분포**: 몰리는 분포(멱법칙·지프형). 상위 약 5%가 전체 제보의 30% 안팎, 대부분(약 60%)은 1~2건. 검증·투표·재확인만 하는 사람도 일부 둔다.
- **닉네임**: 가상 조합(형용사+명사+숫자 등), 실명 쓰지 않음, 300개 중복 없음.
- **이력 순서**(접수일이 항상 가장 앞): 접수 → 검증(시민 2명 투표 또는 검증자) → 접수(민원) → 배정 → 조치 중 → 조치 완료 → 재확인 → (일부) 재발(같은 지점·유형 새 접수). 단계 간격은 현실적으로(배정 1~3일, 조치 시작 2~10일, 조치 완료 3~30일, 재확인 1~7일). 반려·합침 소수(각 3~5%).
- **상태 분포 목표**: 전체 중 조치 완료+재확인 완료 약 40%(처리율), 기한 경과 몇 건(10~15%), 재발 지점 몇 곳(5~10%), 검증 대기·이관 요청 소수.
- 점수 규칙을 어기지 않는다: 하루 점수 상한(`rewards.ts`/`config.ts`) 안에서 한 사람이 같은 날 너무 많이 제보하지 않게 분산. 투표자는 본인 제보에 투표하지 않는다(같은 건 중복 투표 없음).
- 접수번호: `DEMO-LRG-NNNN`(기존 `DEMO-SIM-`과 구분).
- 설명 문구: 유형별 짧은 문장 몇 종 + "(시연)" 접두. 처리 메모도 "(시연)".

## 4. 발표 장면 보호
- `docs/발표_시연_시나리오.md` 2~5장이 쓰는 지점·상태(기존 10건: R16·B02·R17·W-C·R19(+재발)·B03·R18·N01·R15-1)는 그대로 둔다. 대규모 건은 이 지점의 15m 안에 두지 않는다(중복 경고·재발 판정·재확인 대기 목록이 바뀌지 않도록). 시민 B·C 계정이 재확인할 건(B03 한 건)이 대규모 데이터 때문에 늘거나 줄지 않게, 대규모 건 중 "재확인 대기"는 `crowd-*` 사용자가 제보한 건으로만 만든다(챌린지 카드 숫자가 늘어나는 것은 허용하되 B03이 사라지지 않을 것).
- 가상 지점 위치는 기존 10건 지점·팀 조사 34곳과 겹치지 않게 간격 두기(최소 20m 이상 권장).

## 5. 데이터 형식과 내보내기·가져오기
- 시연 도구에 **"시연 데이터 내보내기 / 가져오기"**(파일). 같은 JSON 형식을 읽고 쓴다.
- 형식(`wheelmap-demo` v1):
  ```json
  {
    "format": "wheelmap-demo", "version": 1, "synthetic": true,
    "generatedAt": "ISO", "seed": 20261111,
    "users": [{ "id": "crowd-001", "nickname": "..." }],
    "reports": [ /* Report[] 그대로 */ ]
  }
  ```
- 가져오기: 형식·version 검사 → 기존 제보에 **합치기가 아니라 대체**(기존 demo 건만 대체, 실제 사용자가 만든 건은 보존) 또는 안내창으로 선택. 잘못된 파일은 거부하고 메시지. 크기 상한(예: 8MB) 검사.
- 생성 스크립트 `scripts/genDemo.ts`가 같은 모듈(`src/lib/demoLarge.ts` 같은 순수 함수)로 `data/demo/large-demo.json`을 만든다(팀원 폰에 가져오기). `now`는 스크립트 실행 시점이므로, 팀원이 가져올 때 날짜가 다시 밀리지 않게 JSON에는 `generatedAt`과 함께 날짜를 그대로 두고, 가져오기 때 `generatedAt`과 지금의 차이만큼 모든 날짜를 평행 이동(옵션, 기본 켜짐)한다.

## 6. 표시
- "대규모 시연 데이터를 채운 동안"(= `demoSet:'large'` 건이 하나라도 있는 동안) 지도 위쪽 띠(`MockStrip` 옆)에 **"시연용 가상 데이터 · 실제 제보가 아니에요"**를 항상 보인다.
- 핀 상세(제보 상세 `ReportDetail`, 지점 상세)에 같은 문구의 작은 배지.
- 행정 화면·랭킹·보고서에도 띠가 보이면 좋으나 필수는 지도 띠+핀 상세.

## 7. 사용자 명부
- 닉네임 명부를 별도 localStorage `wheelmap.demoCrowd.v1`(id→닉네임)에 저장하거나 reports와 같은 저장 단위로 둔다. `userName(id)`이 `DEMO_USERS` → 명부 → SYSTEM_NAMES 순으로 찾는다. 시연 사용자 선택 목록(5명)은 그대로.
- 랭킹 화면에서 300명의 닉네임이 나오고, 내 줄은 기존 5명 중 현재 사용자가 있으면 그대로 강조.

## 8. 검증 항목(구현 뒤)
1. 계산 코드로 집계: 처리율, 기한 경과 건수, 재발 건수, 상태 분포.
2. 규칙: 하루 점수 상한, 단계 날짜 ≥ 접수일, 투표자 ≠ 제보자·중복 없음, 접수번호 유일.
3. 규모: 300명 랭킹 표시 시간, 지도 핀 150여 개 표시, localStorage 용량(제보 700건 이력 JSON 크기, 한도 약 5MB), 초기 로딩·채우기 소요 시간.
4. 화면(메인): 랭킹 이번 주/이번 달, 개선 현황 지도, 보고서, 부서별, 가상 표시, 기존 시나리오 2~5장 그대로.

## 9. 하지 않는 것
- 사진 생성(조치 전후 비교는 못 보여 줌), 새 TMAP 호출(길찾기는 저장된 경로 쌍만), 실제 사람 이름·실제 신고 내용.
- 커밋·push는 사용자가 요청할 때.

## 구현 메모
(구현 2026-11-11, worker)
- **규모가 설계보다 작다**: 용봉동 주소의 위치 후보는 횡단보도 16·정류장 55·편의시설 20 = 91곳뿐이다(장애인화장실은 주소와 좌표가 어긋나 제외). 여기서 기존 시연 지점(시나리오 2~5장) 40m 안, 팀 조사 지점 26m 안, 가상 지점끼리 20m 안을 빼면 **가상 지점 57곳**이 남는다. 그래서 제보도 설계 하한 쪽인 **640건**으로 잡았다(지점당 평균 약 11건, 같은 곳에 여러 사람이 올린 것으로 본다).
- 기존 10건과의 거리는 설계의 15~20m보다 넓은 **40m 이상**으로 했다(재발 판정 30m + 위치 흔들림 3m 여유). 실제 최소 거리 약 44m. 가상 건 좌표는 지점에서 최대 3m 흔든다.
- 이웃 지점(45m 안)은 같은 유형을 쓰지 않는다(재발 판정이 지점 사이로 번지지 않게). 같은 지점·유형의 건은 모두 서로 먼저 접수된 뒤에 조치되도록 시각을 맞췄고, 재발은 지점의 약 9%(5곳, 재발 건 7)만 일부러 만든다.
- 유형: 설계서의 "신호기(횡단보도) 6%·기타"는 `reportTypes.ts`에 없는 유형이라, 신호기 6%는 **입간판·노점**으로 대신하고 기타는 킥보드·공사 자재·경사로 없음·수동문·장애인화장실 없음으로 나눴다. 소관 기관 후보가 없는 조합(쓰레기+버스정류장 등)은 `findAgencies`로 걸러 만들지 않는다. 정류장·편의시설 지점도 앞 보도의 불편은 "구·시 도로의 보도"로 접수한다.
- 이력에 모든 건이 `(시연)`을 달고, 접수 채널은 안전신문고 70%·국민신문고 30%, 접수번호는 `DEMO-LRG-NNNN`(접수된 건만), 반려 사유는 `REJECT_REASONS` 중에서 고른다. 이관은 처리 중 건의 일부(요청·수락·반려)에만 둔다.
- **재확인 대기 목록이 길어진다**: 대규모를 채우면 조치 완료(재확인 전) 건이 약 98건 생겨 시민 B·C의 "재확인 대기"가 길어진다. 시나리오 5장의 B03은 그대로 있지만 목록에서 찾아야 한다(대규모 건의 제보자는 모두 `crowd-*`).
- 가져오기·내보내기: 내보내기는 `demo` 건 전체(기존 10건 포함)와 가상 사용자 명부를 담고, 가져오기는 기존 `demo` 건을 모두 파일 내용으로 바꾼다(실제 제보는 보존). 사진이 들어 있거나 `demo`가 아닌 건이 섞인 파일, 8MB 초과, 형식·버전·날짜·좌표가 어긋난 파일은 통째로 거부한다. 날짜 이동은 `generatedAt`과 지금(시연 시각)의 차이만큼 모든 ISO 날짜를 옮긴다.
- 사용자 명부는 `wheelmap.demoCrowd.v1`(generatedAt + id→닉네임). 랭킹은 시연 사용자 4명 + 명부 300명을 모두 계산하되, "기록 없는 사람" 줄에는 시연 사용자만 이름을 적고 나머지는 "외 N명"으로 줄였다. 홈의 이번 주 순위도 같은 명부를 쓴다.
- 스크립트: `node scripts/genDemo.ts [--now=ISO]`가 `data/demo/large-demo.json`을 만든다. 앱 코드가 확장자 없는 import·JSON import를 쓰므로 `scripts/registerTs.mjs`·`tsHook.mjs`(Node 해석 도우미)를 같이 두었고, 앱 코드는 고치지 않았다. 검증은 `node scripts/verifyDemo.ts [--file] [--debug]`.
- 검증 결과(now=생성 시점, 시드 20261111): 처리율 41%(조치 완료+재확인 / 기관 접수), 기한 경과 16%(목표 10~15%보다 약간 높음), 하루 점수 상한 위반 0, 상위 5%의 제보 비중 37%, 제보 1~2건 사용자 60%. 처리율·기한 경과는 접수 후 14일 기준(안전신문고 기본 기한)이라 최근에 몰린 분포(0~7일 32%)로 맞췄다.
