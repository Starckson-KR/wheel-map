# 외부 접수·조회 API 조사 (국민신문고·안전신문고)

- 조사일: 2026-11-10 (웹 공개 정보만 확인. 로그인 필요한 화면은 시도하지 않음)
- 한계: 검색 도구와 요약 도구로 확인한 결과이며, 약관 원문 전체와 공공데이터포털 목록 전체를 직접 열람하지는 못했다. 아래 "확인 안 됨"은 "없다"가 아니라 "공개 자료에서 근거를 찾지 못했다"는 뜻이다.

## ① 한 줄 결론

앱이 국민신문고·안전신문고에 민원을 대신 접수하거나 접수번호로 처리 상황을 받아올 수 있는 공개 외부 API는 확인되지 않았다. 공개된 것은 민원 통계·처리예외일 같은 조회용 데이터뿐이다. 따라서 이 프로토타입은 실제 연동 대신 "공식 창구로 안내하고 접수번호를 사용자가 직접 입력해 기록"하는 방식이 현실적이다.

## ③ 앱에 반영할 수 있는 현실적 선택지

1. 공식 창구로 안내하고 접수번호는 사용자가 입력 (권장)
   - 방식: 제보 내용을 복사하기 좋게 정리해 보여 주고 국민신문고·안전신문고 링크를 연다. 접수 후 받은 접수번호를 앱에 직접 적어 두게 하고, 조회는 공식 조회 화면 링크로 연결한다. 현재 getMockStatus는 "모의 데이터" 표시를 유지한다.
   - 장점: 약관·인증 위험이 없고 지금 바로 가능하며 "역분석·스크래핑 안 함" 원칙에 부합한다.
   - 단점: 자동 접수·자동 상태 갱신은 없다. 사용자가 두 번 입력해야 한다.
2. 공식 제도 문의 후 정식 연계 제안 (발표 이후 확장안)
   - 방식: 국민권익위원회·행정안전부(디지털서비스 개방 공모)·북구청에 연계 가능 여부를 공문·문의로 확인한다. 발표에서는 "정책 제안"으로 제시한다.
   - 장점: 정책 난제 과제의 취지에 맞고 제도 개선 제안이 된다.
   - 단점: 시간이 걸리고 학생 팀 단독 신청은 어려울 가능성이 크다(확인 안 됨).
3. 공공 통계 API로 "재발·통계" 화면만 보강
   - 방식: 민원빅데이터 분석정보 API(조회 전용)로 지역·분야별 민원 건수를 미리 받아 JSON으로 저장해 참고 지표로 쓴다(키는 브라우저 코드에 넣지 않음).
   - 장점: 공개 API라 합법적이고 안전하다.
   - 단점: 개별 민원의 접수·상태와는 무관하다. 비영리·출처표시 조건을 지켜야 한다.

## ④ 사용자에게 확인할 것

1. 발표에서 "실제 접수 연동은 제도상 공개 API가 확인되지 않아 링크 안내 방식"이라고 설명해도 되는지.
2. 선택지 2(관계기관 문의)를 할 경우, 누가 어디(권익위·행안부·북구청)에 문의할지. 문의 전에는 확정적인 표현을 쓰지 않는다.
3. 광주광역시·북구청 자체 민원창구(시민의 소리 등)가 발표 대상 민원에 쓰이는지. 이번에는 확인하지 못했으므로 사용자가 해당 누리집 주소를 알려 주면 추가 조사하겠다.
4. 국민신문고·안전신문고 약관 원문 확인이 필요한지(필요하면 사용자가 하단 이용약관 페이지를 직접 열어 확인하는 것이 가장 확실하다).
