# 7단계 저상버스 결과 (2026-10-30)

## TMAP 대중교통 API 확인 (사용자 질문 답)
- 공식 문서(transit.tmapmobility.com): `POST https://apis.openapi.sk.com/transit/routes`, 헤더 appKey, 버스·지하철·기차 등과 도보 구간을 조합해 경로를 준다. 지원 지역 목록은 문서에 없고, 지역 밖이면 오류 23(서비스 지역 아님)을 돌려준다.
- 요금: FREE 하루 10건(초과 시 자동 차단), 종량제 건당 0.88원(후불). 신청은 SK open API에서 앱을 만든 뒤 상품을 구매(요금제 선택)하는 방식이다.
- 시험 호출 1회: 현재 TMAP_APP_KEY로 HTTP 200, 광주(용봉동 → 전대치과병원) 버스 경로가 정상 응답했다. 즉 상품 신청은 이미 되어 있고 광주도 지원된다. 하루 한도가 10건이라 개발 중계에 하루 8회 상한(`scripts/transitClient.ts`의 `TRANSIT_DAILY_CAP`)과 캐시를 두었다. 유료로 바꾸면 이 값만 올리면 된다.
- 결론: TMAP은 필요하다. 보행자 경로(걷기)와 대중교통 경로(버스)를 모두 같은 키로 쓴다.

## 구현한 것
1. 실시간 저상버스(개발판): vite 중계 `/wheel-map/__bis/arrive?station=`, `/__bis/line?name=`. 키는 서버에서만 쓰고 25초 캐시, 하루 200회 상한. 정류장 카드에 "다음 저상버스 ○○번 3분 후(2정거장 전)", 일반과 저상 구분, 없으면 "곧 오는 저상버스가 없어요", 정류장의 버스 타기 불편(X·△)이 있으면 경고를 함께 보여 준다.
2. 배포판: 실시간 대신 한 시점 스냅샷(`data/public/bus-snapshot.json`, 정류소 16곳·노선 7개, 수집 시각 표기, "실시간이 아니에요" 명시). 공급자 인터페이스는 `src/lib/bus/provider.ts`. 환경변수 `VITE_BUS_RELAY_URL`에 Cloudflare Workers 같은 중계 주소를 넣으면 배포판도 실시간이 된다(파일 안 주석에 만드는 법 메모).
3. 정류장 레이어는 기본 지도에 되살리지 않고 길찾기 결과의 출발·도착 근처 정류장(BIS 기준으로 교체)과 시범 정류장 상세에서만 정보를 준다.
4. 대중교통+보행: "걸어서 / 버스 타고" 탭. 걷는 구간은 기존 엔진(장애요소 검사·우회, 구간당 요청 3번 제한), 탑승·하차 정류장에서만 boarding 장애요소를 판정에 넣는다. X이면 "휠체어 탑승이 어려워요"와 대안(정류장을 쓰지 않는 다른 경로, 200m 안 다른 정류장)을 보여 준다. 노선별 운행 저상 대수(busLocationInfo)도 표시한다.

## 시범 정류장 짝짓기 (`data/public/pilot-stops.json`, 좌표 40m 이내)
- R15-1 → 1004(4m), R15-2 → 1003(11m, 반대편 1004 33m 후보), R16 → 644 북구보건소(4m), B03 → 1008(8m, 반대편 1007 31m), B07 → 1208 전대치과병원(8m): 모두 확정.
- B02(용봉휴먼시아, 영역) → 869 용봉2휴먼시아아파트 34m: **애매**(이름이 다르고 25m 초과). 화면에 확인 필요로 표시한다.

## 호출 수
BIS 약 30회(상한 50), TAGO 0회, TMAP 4회(대중교통 시험 1 + 시연 3쌍 3).

## 관찰
- 419번(p2 경로)과 518번(p3)은 수집 시각에 운행 중 저상버스가 0대였다. 진월07·문흥18·일곡28·봉선27은 대부분 저상.
- p2는 R15 정류장이 X라 버스 경로가 모두 "어려움"으로 나온다(팀 조사 평가를 그대로 반영).

## 한계
- 도착 정보는 예정 시간이며, 실제 휠체어 승차 가능 여부는 보장하지 않는다.
- 버스 경로 새 검색은 개발 모드에서만 가능하고 하루 한도가 있다. 배포판은 시연 3쌍만.
- BIS `LOW_BUS=1`이 저상이라는 해석은 응답 관찰 기준(가이드에 값 설명 없음).
- 걷는 구간 우회는 저장본이 없는 조합이라 배포판에서는 확인하지 못한다.
