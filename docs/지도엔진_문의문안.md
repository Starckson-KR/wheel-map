**보내는 곳**
- 카카오: 카카오 데브톡 새 글 작성(게시판 주소는 확인 필요). 참고한 기존 답변 글: https://devtalk.kakao.com/t/api/152352
- 토스(앱인토스): 채널톡 https://apps-in-toss.channel.io/

**보내기 전 확인할 것**
- 두 문안에는 실명·학번·연락처·이메일을 넣지 않았습니다. 데브톡은 계정 정보로 답변이 오고, 채널톡은 접수 화면의 연락처 입력란에 사용자가 직접 적습니다.
- 앱 이름(`appName`)은 아직 정해지지 않아 `<appName>`으로 두었습니다. 도메인 형식 `<appName>.apps.tossmini.com`은 조사 문서(2026-10-28)에 따른 것이므로 보내기 전에 콘솔 안내와 다시 맞춰 봅니다.
- 조사 문서의 카카오 답변 인용은 요약본입니다. 데브톡 원문(위 링크)을 읽고, 아래 문안 1의 질문 ①에 쓴 표현이 원문과 맞는지 확인한 뒤 보냅니다.

## 문안 1. 카카오 데브톡(카카오 개발자 문의)용

**제목:** 카카오맵 JavaScript SDK를 토스 앱인토스 미니앱(웹뷰)에서 사용할 수 있는지 문의드립니다

안녕하세요. 북구동행지도 개발팀입니다.

저희는 휠체어 이용자의 이동경로에서 장애요소를 지도 위에 보여 주고 시민 제보를 소관 기관 민원으로 연결하는 웹 서비스를 대학원 수업 과제로 만든 비상업 교육 목적 프로토타입입니다. 현재 카카오맵 JavaScript SDK(지도 표시, 장소 검색, 지오코더)를 웹 서비스에서 사용하고 있습니다.

이 웹을 토스의 앱인토스 미니앱(토스 앱 안의 웹뷰)으로도 배포하려고 합니다. 미니앱은 `https://<appName>.apps.tossmini.com` 도메인으로 제공됩니다. 이와 관련해 아래 사항을 문의드립니다.

1. 앱인토스 미니앱 도메인(`*.apps.tossmini.com`)을 저희 카카오 개발자 앱의 JavaScript SDK 웹 도메인으로 등록해 사용할 수 있나요? 기존 데브톡 답변에서 "같은 서비스에서 개발자 앱을 여러 개 사용할 수 없고, 토스 안에서 지도가 필요하면 해당 플랫폼 제공자에게 요청하라"고 안내하셨는데, 이 안내가 위와 같은 경우(저희가 직접 만든 앱의 키를 토스 웹뷰 안에서 쓰는 경우)에도 그대로 적용되는지 알고 싶습니다.
2. 앱 안의 웹뷰에서 JavaScript SDK를 사용할 때 이용약관이나 정책상 제약이 있나요?
3. 상업적 목적이 없는 교육용 프로토타입인 경우 위 답변이 달라지는 부분이 있나요?
4. 사용이 어렵다면, 이 경우 권장하시는 대안이 있나요? (예: REST API 사용, 정적 지도 이미지 등. 각 방식의 이용 범위도 함께 안내해 주시면 감사하겠습니다.)

바쁘신 중에 번거롭게 해 드려 죄송합니다. 확인해 주시면 큰 도움이 되겠습니다. 감사합니다.

## 문안 2. 앱인토스(토스) 개발자 문의(채널톡)용

**제목:** 앱인토스 미니앱의 외부 지도 SDK 사용 및 시민 제보형 서비스 출시 관련 문의

안녕하세요. 북구동행지도 개발팀입니다.

저희는 휠체어 이용자의 이동경로에서 장애요소(단차, 좁은 보도, 경사 등)를 지도 위에 보여 주고 시민 제보를 소관 기관 민원으로 연결하는 서비스입니다. 현재 Vite + React로 만든 웹(WebView SDK 방식 예정)이며, 대학원 수업에서 만든 비상업 프로토타입입니다. 출시 전에 아래 사항을 확인하고 싶습니다.

1. 외부 지도 SDK: 미니앱에서 외부 지도 SDK(카카오맵 JavaScript SDK)의 스크립트를 로드하고 외부 도메인을 호출해도 되나요? 허용된다면 CSP나 허용 도메인을 등록하는 방법을 알려 주세요.
2. 지도 컴포넌트: 토스가 제공하거나 권장하는 지도 컴포넌트·SDK가 있나요?
3. 기기 기능: 위치 권한(`navigator.geolocation` 또는 SDK의 위치 API 중 어느 쪽을 써야 하는지), 카메라 및 사진 첨부(`<input type="file">` 동작 여부 또는 `openCamera` 사용), localStorage/IndexedDB 사용이 가능한지 알려 주세요.
4. 서비스 유형: 시민 제보형 공익 서비스(사진·위치 첨부, 기관 민원 안내)가 입점할 수 있는 카테고리와 심사 가능 여부, 그리고 사업자 없이 개인(학생) 신분으로 출시할 때의 제약이 있는지 알려 주세요.
5. 시연용 기능: 제보를 실제 기관에 접수하지 않고 접수 흐름만 보여 주는 모의 기능이 있습니다. 출시 버전에는 실제 기관 접수가 아님을 화면에 분명히 표시할 예정인데, 이런 기능이 포함된 버전을 심사에 제출해도 되는지 알려 주세요.

번거롭게 해 드려 죄송합니다. 확인해 주시면 큰 도움이 되겠습니다. 감사합니다.

## 답변에 따른 다음 행동

지도 엔진 교체 후보는 조사 문서(P0-1)에 적힌 것만 씁니다: OpenStreetMap 타일 + Leaflet/MapLibre, 네이버 지도, TMAP 지도 SDK. 세 후보 모두 약관·키·토스 안 동작은 **아직 미확인**이므로 채택 전에 각각 확인합니다.

| 답변 조합 | 우리 앱 대응 |
|---|---|
| 카카오 가능 + 토스 외부 SDK 허용 | 카카오맵 유지. 토스가 안내한 CSP·허용 도메인 등록 절차와 카카오가 안내한 도메인 등록 방식을 따르고, 조사 문서의 P1·P2 항목(권한·저장소·빌드 분기)을 진행합니다. 토스 앱 QR 테스트에서 지도가 실제로 뜨는지 확인합니다. |
| 카카오 불가 (토스는 허용) | 앱인토스용 빌드만 지도 엔진을 교체합니다. 지도 엔진을 어댑터로 추상화(`KakaoMap.tsx`·`kakao.ts`·지오코더·장소 검색 분리)하고, 후보(OSM 타일 + Leaflet/MapLibre, 네이버 지도, TMAP 지도 SDK)의 약관·타일 이용 정책·토스 내 동작을 확인해 사용자가 승인하면 적용합니다. 장소 검색·지오코딩은 미리 받은 JSON을 쓰거나 서버 중계를 둡니다. 카카오가 안내한 대안(REST·정적 지도)이 있으면 함께 비교합니다. GitHub Pages 판은 카카오맵을 그대로 둘 수 있습니다. |
| 토스가 외부 SDK 불허 | 외부 스크립트가 필요 없는 방식으로 갑니다. 토스가 제공·권장하는 지도 컴포넌트가 있으면 그것을 우선 검토하고, 없으면 번들에 포함 가능한 라이브러리(Leaflet/MapLibre 등)로 교체하는 안을 검토합니다. 타일은 외부 서버 호출이 필요할 수 있어 이 호출이 허용되는지도 토스에 다시 확인합니다. 모두 막히면 앱인토스 출시는 보류하고 GitHub Pages 웹으로 유지하는 선택지를 사용자에게 보고합니다. |
| 토스가 시민 제보형·모의 기능을 불허하거나 조건 부여 | 출시판에서 시연 도구를 제거하고 `COMPLAINT_MODE=link`만 남기며, 외부 접수 링크는 보조 경로로 둡니다. 카테고리 제약이 있으면 서비스 소개 방식을 조정하거나 출시 여부를 다시 판단합니다. |
| 답변이 오래 걸리거나 불명확 | 두 곳 모두 재문의하고, 그동안 지도 어댑터 분리 같은 엔진과 무관한 작업만 진행합니다. |
