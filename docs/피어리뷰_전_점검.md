# 피어리뷰 전 점검 (2026-11-15)

> 처음 써 보는 사람의 눈으로 앱 전체를 본 결과다. 코드와 데이터는 고치지 않았고, 고칠 것은 번호로 골라 주시면 된다.
> 본 환경: 개발 서버 localhost:5173(빌드 3bc1d30+dirty), 휴대폰 375×812 기준, PC 1280은 홈·지도·행정만. 라이트·다크 모두 봤으나 다크는 홈·민원신고 위주다. 배포판(starckson-kr.github.io/wheel-map, 빌드 1e2b9a4)은 홈·길찾기 한 화면만 비교했다.
> 상태 두 가지: 가 = 새 컨텍스트 첫 접속(데이터 없음), 나 = 시연 도구의 "대규모 시연 데이터 채우기" 후.
> 난이도: 작음(문구·CSS 몇 줄) / 중간(화면 한 곳 구조 변경) / 큼(데이터·여러 화면).

## 1. 한 줄 요약

기능은 끝까지 돌아가고 콘솔 오류도 없지만, 리뷰어가 데이터 없이 들어오면 "소식 4칸이 모두 '없어요'", 지도엔 "위치 임시" 표시가 가득, 내 제보는 검증 대기에서 멈춰 앱이 비어 보이고, 개발 배지·팀 내부 메모·"시연/개발" 문구가 그대로 보이는 것이 가장 큰 약점이다.

## 2. 꼭 고칠 것 (리뷰 전)

**1. 첫 접속 빈 화면: 체험 데이터 안내 카드가 없다** (홈, 동행지도, 내 정보, 혜택알림)
- 현상(가): 홈 "소식"이 "처리 중인 내 민원이 아직 없어요 / 참여 점수 0점 / 재확인 기다리는 민원이 없어요 / 확인 기다리는 제보가 없어요" 네 칸으로 모두 빈 상태 안내다. 내 정보는 "아직 칭호가 없어요 0점", 랭킹·재확인·확인 투표도 비어 있다. 이를 채우는 "대규모 시연 데이터 채우기"는 지도 > 레이어 버튼 > 맨 아래 "화면·발표 도구 > 시연 도구" 안에 있어 리뷰어가 찾을 수 없다.
- 현상(나): 채운 뒤에도 현재 사용자인 시민 A 기준으로는 홈이 "처리 중인 내 민원이 아직 없어요 / 0점"이고 "확인을 기다리는 제보가 87건"만 바뀐다. 채워도 홈이 거의 그대로다.
- 왜 문제: 피드백의 대부분이 "랭킹, 개선 현황, 행정 화면이 빈다"는 것이 될 수 있다. 앱이 무엇을 하는지 보여 줄 데이터가 없다.
- 고치는 방법: 데이터가 없을 때 홈 맨 위(그리고 동행지도 첫 진입)에 한 번만 뜨는 카드 "처음이세요? 체험 데이터를 채우면 지도·랭킹·행정 화면이 채워져요 [체험 데이터 채우기] [그냥 둘러보기]". 버튼은 기존 대규모 채우기 함수를 그대로 부르고, 채운 뒤 "가상 데이터예요. 설정 > 시연 도구에서 지울 수 있어요" 토스트와 함께 동행지도로 보낸다. 시민 A의 제보 몇 건(접수·조치 단계별)을 같이 채우면 홈 소식과 내 정보도 살아난다.
- 난이도: 중간

**2. 개발 배지가 배포판에도 계속 보인다** (모든 화면 맨 위)
- 현상: 빨간 "Development In Progress · build 3bc1d30+dirty"가 화면 맨 위에 고정이다. 배포판에서도 "…build 1e2b9a4"로 보인다. 모바일에서 헤더·"시연용 가상 데이터" 띠와 겹쳐 글자가 가려진다(지도 화면에서 확인).
- 왜 문제: 빌드 해시, "dirty"가 그대로 보여 미완성 인상을 주고, 겹치는 곳은 읽기도 어렵다.
- 고치는 방법: 배포 빌드에 `VITE_SHOW_DEV_BADGE=false`를 넣는다(코드는 이미 지원). 남기고 싶다면 화면 아래 모서리로 옮기고 해시를 뺀다. `.github/workflows/deploy.yml`은 다른 작업이 고치는 중이라 건드리지 않았다.
- 난이도: 작음

**3. 팀 조사 핀 상세에 내부 메모가 그대로 나온다** (동행지도 > 팀 조사 핀 > 상세, 예: 치과병원 앞 횡단보도)
- 현상: "평가 출처: 팀원 B 표", "조사 정보 팀 현장조사 · 조사자 팀원 B · 조사일 정보 없음", "확인이 더 필요해요: 팀원 B 최종 평가 산정 규칙이 일관되지 않음(신안교 C01은 …, 2장 ③) / 점자블록은 범위 밖…재해석 필요(2장 12)", "사진 4장 · 내부 확인용이라 개발 서버에서만 보여요", "민원 진행 (시연): 팀이 조사한 지점을 검증이 끝난 것으로 보고 접수 안내부터 시연해요". 
- 왜 문제: 핀을 눌러 상세를 여는 것이 앱의 중심 동작인데, 열자마자 팀 내부 작업 메모가 보인다. 교수님 앞에서 가장 어색하다.
- 고치는 방법: 사용자에게 보이는 상세에서는 "확인이 더 필요해요" 항목의 내부 참조(문서 장 번호, 팀원 이름)를 빼거나 "현장조사 결과(팀 조사)"처럼 공개용 문구로 바꾼다. 사진 안내는 "사진은 공개 배포판에서는 보이지 않아요"가 아니라 사진 영역 자체를 숨긴다. 데이터(seed)를 고치는 것이므로 사용자가 확인할 문구를 정해 주셔야 한다. 이 상세를 본 곳은 개발 서버뿐이고 같은 데이터이므로 배포판도 같다고 본다(배포판에서 직접 열어 보지는 않음).
- 난이도: 중간

**4. 첫 화면에서 앱의 목적이 3초 안에 전달되지 않는다** (홈)
- 현상: 홈 맨 위는 "북구동행지도"라는 이름, 이어서 "이용 안내 확인하기"(접힌 카드, 아이콘이 오른쪽 위 "알림" 종과 같다), "AI 검색 / 궁금한 걸 적으면 알맞은 화면을 찾아 드려요", 검색창이다. 이용 안내를 펼쳐도 내용은 "발표용 시연 프로토타입이에요. 민원 접수는 실제로 보내지지 않아요." 한 줄뿐이다. 앱이 휠체어 이동 장애요소를 지도에 모으고 신고·개선까지 잇는 서비스라는 말이 어디에도 없다.
- 왜 문제: 처음 온 사람이 "이게 무슨 앱인가"를 스스로 추측해야 한다.
- 고치는 방법: 이름 바로 아래에 한 줄 소개("휠체어로 지나가기 어려운 곳을 지도에서 확인하고, 신고하고, 개선되는 과정까지 함께 봐요"), 이용 안내를 3단계(찾기 → 신고하기 → 개선 확인)로 바꾸고 아이콘을 종이 아닌 물음표·정보 아이콘으로 바꾼다. "발표용 시연 프로토타입"은 "수업 프로토타입이에요. 민원은 실제로 접수되지 않아요"처럼 리뷰어 눈높이로 바꾼다. 1번 카드와 한 묶음으로 만들면 좋다.
- 난이도: 작음

**5. 제보 흐름: 사진이 필수인데 표시가 없고, 사진이 없는 리뷰어는 끝까지 못 간다** (민원신고 > 제보 3/4)
- 현상: 라벨이 "사진 1~3장"이고 "필수"라는 말이 없다. "다음"을 눌러야 "사진을 1장 이상 올려 주세요"가 나온다. 안내에 "긴 변 1280px로 줄여 저장" 같은 기술 용어가 있다. 노트북으로 보는 리뷰어는 올릴 현장 사진이 없을 수 있다.
- 왜 문제: 제보를 끝까지 해 보는 것이 가장 핵심 체험인데 여기서 막힌다.
- 고치는 방법: 라벨에 "(필수)"를 붙이고, 사진 영역에 "예시 사진으로 체험하기" 버튼(앱에 넣어 둔 샘플 1장)을 둔다. 안내는 "얼굴과 번호판이 나오지 않게 찍어 주세요. 사진은 이 기기에만 저장돼요"로 줄인다.
- 난이도: 작음(필수 표시·문구), 중간(샘플 사진 버튼)

**6. 제보를 올린 뒤 "그다음"이 보이지 않는다** (제보 완료 화면, 제보 상세, 내 민원 진행 상황)
- 현상: 완료 화면은 "제보를 등록했어요. 지금은 '검증 대기' 상태예요"까지만 말하고 접수번호도 다음 단계도 없다. 내 제보 상세는 "내 제보는 내가 확인할 수 없어요. 시연 도구에서 다른 시민이나 검증자로 바꿔 보세요."라고 맨 아래 작은 글씨로 안내한다. 지도에도 내 제보가 나타나지 않는다(검증 전이라 0건). 그래서 혼자 하는 리뷰어는 "접수번호를 찾아 진행 상황 보기" 과제를 끝낼 수 없다.
- 왜 문제: 접수 → 검증 → 조치 → 재확인이라는 사업의 핵심 순환을 리뷰어가 체험하지 못한다.
- 고치는 방법: 완료 화면에 "이렇게 진행돼요: 시민 2명 확인 → 민원 접수(접수번호 발급) → 조치 → 재확인" 흐름 4단계를 넣고, 바로 아래에 "체험: 검증자로 확인해 보기" 버튼(사용자를 검증자로 바꾸고 검증 완료 → 접수까지 한 번에)을 둔다. 시연 도구를 쓰는 사람에게는 영향이 없다.
- 난이도: 중간

**7. 위치가 위도·경도 숫자로만 나오고, 목록 항목이 서로 구분되지 않는다** (제보 확인 4/4, 제보 상세, 동행지도 목록, 행정 민원함)
- 현상: "버스정류장 · 위도 35.16612, 경도 126.91019". 지도 목록과 행정 민원함은 "시민 제보 · 파손 노면 / 조치 중"이 수십 줄 똑같이 이어지고, 어디인지 알 수 없다(행정 민원함은 접수번호만 다르다). 지도에서 항목을 눌러도 상세 위치가 숫자다.
- 왜 문제: 사용자가 알아볼 수 없는 값이고, 목록에서 찾고 싶은 항목을 고를 수 없다.
- 고치는 방법: 카카오 좌표→주소(이미 쓰는 SDK의 지오코더 또는 동 이름)로 "용봉동 123-4 근처"를 표시하고, 목록 제목에 동·도로명을 붙인다. 대규모 데이터는 생성 시 가상 지점명 필드로 채워도 된다.
- 난이도: 중간

**8. 지도에 "위치 임시"가 가득하다: 팀 조사 지점 20곳 중 18곳의 좌표가 미확정** (동행지도 전체, 지도 위 표시와 "이 지역 장애요소" 목록)
- 현상: 지도 위 점선 "임시" 뱃지가 여러 개(예: 용봉초 인근, 광주역 인근)이고, 목록 아래에 "위치 임시 18곳"과 "광주역 1번(주) 출구 진입로 / 위치 임시 · 아직 확인 전이에요"가 18줄 반복된다. "지도에 아직 없는 곳 2곳"도 있다. 콘솔에는 같은 경고 "위치가 없음: N02, W-B, R01…"가 5번 반복된다.
- 왜 문제: 앱의 핵심 데이터가 미완성처럼 보인다. 다만 좌표는 사용자가 지도에서 확인한 뒤에만 확정한다는 원칙이 있어 임의로 채울 수 없다.
- 고치는 방법: (작음) 임시 지점은 목록에서 "위치 확인 중인 곳 18곳 ▾" 한 줄로 접고, 지도 뱃지 문구는 "임시"에서 "위치 확인 중"으로 바꾼다. (큼) 가능한 지점부터 사용자가 좌표를 확정한다.
- 난이도: 작음(접기·문구) / 큼(좌표 확정)

**9. AI 검색이 장애인화장실 찾기를 신고로 잘못 이해한다** (홈 AI 검색)
- 현상: "휠체어 타고 갈 수 있는 화장실 알려줘" → "이렇게 이해했어요: 문제 신고하기 · 장애인화장실 없음 유형으로 신고 화면을 열어요". 사용자는 장소를 찾았는데 신고 화면으로 이동시킨다. 반면 "집 앞 보도 턱이 너무 높아서 신고하고 싶어"는 "계단·턱 유형으로 신고 화면"으로 정확했고, 무관한 질문("오늘 점심 뭐 먹지")은 "다른 말로 물어봐 주세요."와 예시로 안전하게 답했다. Worker는 3번 호출했다.
- 왜 문제: 리뷰어가 가장 먼저 시험해 볼 법한 질문이고, 앱에는 장애인화장실 지도 레이어가 이미 있다.
- 고치는 방법: Worker 의도 목록에 "화장실·편의시설 찾기 → 동행지도 장애인화장실 레이어 켜기"를 추가하고 "없음 신고"와 구분하는 예시를 프롬프트에 넣는다. Worker 변경이라 키워드 모드(AI 끄기)에도 같은 규칙을 넣는다.
- 난이도: 중간

**10. 혜택알림 탭: 이름과 내용이 달라서 알림과 랭킹이 약 10,000px 아래에 묻힌다** (혜택알림)
- 현상: 탭 이름은 "혜택알림"이고 화면은 맨 위 참여 점수 카드 → 혜택·행사 카드 15개(약 10,000px) → 참여 랭킹 → 이번 주 챌린지 → 맨 마지막 "알림"이다. 실제 알림("계단·턱 제보가 검증을 기다리고 있어요")과 챌린지가 가장 아래다. 맨 처음 보이는 혜택 카드는 "확인 필요 / 이용 대상, 요금, 예약 방법은 공식 안내를 확인하지 못했어요"로 시작해 내용이 빈약해 보인다.
- 왜 문제: "혜택알림(랭킹·챌린지)" 과제에서 목적지를 찾기 어렵고, 첫 인상이 "확인하지 못했어요"다.
- 고치는 방법: 맨 위에 구간 이동 칩(알림 · 혜택 · 랭킹 · 챌린지)을 고정하거나 알림을 최상단으로 올린다. 혜택은 처음 3~4개만 보이고 "더 보기"로 접으며, "확인 필요" 카드는 뒤로 보낸다.
- 난이도: 중간

## 3. 하면 좋은 것

**11. 길찾기 결과가 시트 아래에 숨고 두 길이 거의 같아 보인다** (동행지도 > 길찾기)

## 4. 리뷰에서 나올 법한 질문과 답할 거리

- 실제로 신문고나 안전신문고에 접수되나요? → 접수 방식은 "링크(실제)"(공식 창구로 안내)와 "모의 연동(시연)"으로 나뉘고, 이 프로토타입은 실제 접수를 보내지 않는다. 접수번호 DEMO-…는 모의 번호이고, 제보 상세에 "시연용 모의 연동 · 실제 국민신문고·안전신문고에는 접수되지 않아요"가 명시된다.
- 장애 판정(○△X)은 누가 하나요? → 팀 현장조사 결과가 바탕이고, 시민 제보는 "다른 시민 2명 이상 확인 또는 검증자의 현장 확인" 중 먼저 되는 쪽으로 검증된다. 개선 뒤에는 시민이 재확인해 ○로 바꾼다. 공공데이터는 참고용이고 지나갈 수 있는지를 판정한 것이 아니라고 표시한다.
- 사진·위치 개인정보는? → 사진은 얼굴·번호판을 피해 찍도록 안내하고, 긴 변을 줄여 저장하며 촬영 위치 정보는 지운다. 데이터는 이 기기(브라우저)에만 저장되고 서버가 없다(다른 기기에서는 보이지 않는다).
- 점수·랭킹을 악용하면? → 점수는 검증이 끝난 뒤에만 쌓이고, 중복·반려는 빠지며 하루 상한과 중복 투표 방지가 있다(검증 스크립트 통과). 시민 화면 랭킹은 닉네임이고, 행정 화면은 개인 순위 없이 동 합계만 보여 준다. 랭킹은 "참여를 돕는 보조 기능이고 제보가 적은 곳이 안전하다는 뜻은 아니다"라고 화면에 쓴다.
- AI 검색이 틀리면? → "AI 답변은 참고용이에요"와 함께 "이렇게 이해했어요" 확인 화면을 먼저 보여 주고 이동은 사용자가 누른다. 키워드만 쓰는 오프라인 모드가 있다. 단 9번 같은 오분류가 있다.
- 왜 행정 화면에 로그인이 없나요? → 수업용 프로토타입이라 담당 공무원은 "시연 도구에서 역할을 바꾸는" 방식이다. 실제 도입 시 행정 인증이 필요하다고 답한다.
- 위치가 "임시"인 곳은 왜 많나요? → 팀 조사표에서 속성은 있으나 지도에서 좌표를 확인하지 못한 지점이다. 확인되지 않은 좌표를 지어내지 않는 원칙을 따른 것이다(8번을 고치면 설명이 쉬워진다).
- 혜택 정보는 믿을 수 있나요? → 각 카드에 확인일과 출처를 적고, 확인하지 못한 항목은 "아직 확인하지 못한 것"으로 따로 밝힌다.
- 비슷한 서비스와 무엇이 다른가요? → 지도에 길이 있어도 못 지나가는 곳을 모아 "신고 → 접수 → 조치 → 재확인 → 개선 현황·재발·보고서·예산 연결"까지 순환시키는 점과, 행정 화면(부서별·경로·보고서)을 함께 둔 점이다.
- 휠체어 길찾기는 실제 경로인가요? → 시연 경로는 미리 저장한 3쌍이고, 가장 짧은 길과 돌아가는 길을 장애요소 기준으로 비교한다.

## 5. 확인 못 한 것

- 실제 휴대폰의 터치·제스처: 아래 시트 3단계 스냅·스프링·관성은 마우스 클릭만으로 확인했고(시트가 열리고 닫히는 것까지), 손가락 드래그 느낌은 못 봤다.
- 다크 모드는 홈과 민원신고만 캡처했다. 글자 크게도 같다. 지도·제보 상세·행정·혜택알림의 다크와 글자 크게는 못 봤다.
- 시민 B·C·검증자·담당 공무원으로 바꿔 검증 → 접수 → 조치 → 재확인을 끝까지 하는 흐름과 행정의 처리 버튼, 보고서 인쇄·CSV, 챌린지 완료·칭호 획득은 해 보지 않았다(접수번호 DEMO-LRG-0031 조회와 행정 7개 탭 열람까지만).
- 실제 사진 촬영, 위치 권한 허용 흐름(헤드리스에선 거부·지연 메시지만 확인), 저상버스 실시간 도착, 지도 핀 640개 렌더 속도.
- 배포판은 홈과 길찾기 한 화면만 봤다. 배포판의 핀 상세·제보 흐름은 개발 서버와 같다고 가정했다.
- 글자 대비는 수치를 재지 않았고 눈으로 봤다(라이트·다크 모두 읽기에는 문제가 없었다). 12px 미만 글자는 홈·민원신고·내 정보·혜택알림에서 없었고, 가로 넘침은 행정 화면 모바일폭을 빼면 없었다.
- 점검 중 다른 작업이 `src/pages/BarrierMap.tsx`와 CSS를 고치고 있어 지도 화면이 한때 흰 화면(`colsStyle is not defined`)이었다가 곧 복구되었고, 지도 머리·범례 위치가 중간에 바뀌었다. 지도 관련 지적(2, 7, 8, 18, 19, 20번)은 수정이 끝난 뒤 한 번 더 보는 것이 안전하다. `.github/workflows/`와 `data/benefits/`는 열어 보지도 고치지도 않았다(git status로 변경 중인 것만 확인).
- Worker 호출은 3회 썼다(화장실 질문, 보도 턱 신고 질문, 무관한 질문).
